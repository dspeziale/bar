================================================================================
DESCRIZIONE APP
================================================================================
QuickLunch e' un'app web Flask multi-tenant per gestire un bar/mensa aziendale.
I dipendenti ordinano pasti, prenotano tavoli, usano un wallet prepagato,
accumulano punti fedelta' e prenotano pasti convenzionati aziendali.
Lo staff ha un backoffice completo con ordini, KDS cucina, prodotti, stock,
tavoli, banco POS con QR, magazzino consumabili, report e comunicazioni.

================================================================================
STACK
================================================================================
Backend:   Python Flask 3.x + Flask-SQLAlchemy + Flask-Login + Authlib (Google OAuth)
DB:        SQLite (sviluppo) / PostgreSQL Neon (produzione, Vercel)
Frontend:  Bootstrap 4.6 + AdminLTE 3.2 + Font Awesome 6 Free
Notifiche: Telegram Bot API + Gmail SMTP (credenziali in AppSetting nel DB)
JS extra:  qrcodejs (QR generation), jsQR (QR scanner), SweetAlert2, jQuery
Font:      PT Sans Narrow (Google Fonts)
Design:    Accent #e94560, Navy #0f3460, gradient 135deg; tema chiaro/scuro

================================================================================
ARCHITETTURA
================================================================================
4 Blueprint:
  auth   → /auth           login, register, Google OAuth, logout
  main   → /               dashboard cliente, menu, ordini, tavoli, wallet
  admin  → /admin          backoffice staff
  tenant → /t/<slug>       registrazione per tenant

Multi-tenant:
  Ogni tabella ha tenant_id nullable FK → tenants
  Superadmin (admin@bar.local, is_admin=True, tenant_id=None) vede tutto
  _effective_tenant_id(): tenant_id utente oppure tenant 'default'
  Risorse globali (Table, TableTimeBand, BancoItem): query senza filtro tenant

Migrazioni: _migrate_tenant_columns() con _ensure(table, col, definition)
  → ALTER TABLE idempotente, compatibile SQLite e PostgreSQL
Seed: _seed_defaults() → tenant default, admin, ruoli, categorie, slot, tavoli,
  ingredienti builder (panino/insalata/poke)

Auth access:
  @staff_required → is_admin OR is_staff (ha permesso backoffice)
  @require_permission(perm) → is_admin bypass o check ruoli
  is_staff property: ha almeno uno tra view_orders, manage_orders,
    manage_products, manage_categories, manage_ingredients, manage_stock,
    manage_tables_admin, manage_reservations_admin, manage_slots,
    manage_users, manage_clients, manage_roles, view_reports

================================================================================
FUNZIONALITA' PRINCIPALI
================================================================================
1. Ordini: carrello in session (cart/custom_cart), slot di ritiro o BANCO,
   scalatura wallet, 10 pt per euro, rimborso su cancellazione,
   notifiche Telegram cucina + utente

2. Builder panino/insalata/poke: ingredienti per categoria con max_choices,
   prezzi extra, opzione griglia, label generata, aggiunta a custom_cart

3. Wallet + Fedelta': wallet_balance FLOAT, credit/debit_wallet,
   100 pt → +1.00€ (redeem in blocchi), bonus registrazione (AppSetting)

4. Tavoli + Prenotazioni: fasce orarie con computed_slots(),
   prenotazione per session_start, check-in, alert 10 min prima scadenza
   via polling /admin/tavoli/ping-alerts, notifiche Telegram

5. Banco POS QR: staff genera sessione (token 32char, 10 min), QR code
   nel browser (qrcodejs), polling status ogni 2s; cliente scansiona
   (jsQR), conferma dal wallet → ttype='banco'

6. Pasto Aziendale: membership → DailyFixedMeal del giorno →
   CorporateMealBooking (una opzione/giorno); cancella se > 30 min dallo slot;
   template MealConfiguration per auto-fill; report presenze mensile

7. RBAC: ruoli + permessi M2M, is_admin bypass tutto,
   5 ruoli sistema (superadmin/manager/cassiere/cuoco/utente)

8. Magazzino: ConsumableItem con soglia alert, movimenti delta,
   email automatica al fornitore quando sotto soglia
